# robot26a_urdf パッケージ詳細解説

このパッケージは、対角オムニホイール（X-drive）を搭載したロボットを Gazebo Sim 上でシミュレーションし、ジョイスティック（GameSir Nova Liteなど）で操縦できるように構築されています。

ここでは、「何がどこにあり、どう動いているのか」「どこをいじればどう変わるのか」を詳細に解説します。

---

## 1. 全体アーキテクチャ（情報の流れ）

コントローラーの操作からロボットが動くまで、以下のようにデータが流れていきます。

1. **`joy_node` (ROS 2標準パッケージ)**
   - **役割**: PCに接続されたコントローラーの物理的な入力（スティックの傾き、ボタンの押し込み）を読み取ります。
   - **出力**: `/joy` トピック
2. **`teleop_twist_joy` (ROS 2標準パッケージ)**
   - **役割**: `/joy` の情報を元に、「ロボットにどれくらいの速度で前後左右・回転してほしいか」という指令（Twist）に変換します。
   - **出力**: `/cmd_vel` トピック
3. **`omni_kinematics_node.py` (今回独自に作成したPythonノード)**
   - **役割**: `/cmd_vel`（ロボット全体としての目標速度）を受け取り、**4つのオムニホイールそれぞれの回転速度**を計算（キネマティクス計算）します。
   - **出力**: `/omni_wheel_controller/commands` トピック
4. **`ros2_control` & `gz_ros2_control` (制御マネージャーとGazeboプラグイン)**
   - **役割**: 計算された4つの車輪の回転速度を受け取り、Gazeboの物理シミュレーション空間内の車輪のモーター（ジョイント）に直接力を加えます。

---

## 2. 主要なファイルとそれぞれの関係

### 📁 `launch/gazebo.launch.py`
**すべての起点となる起動ファイル**です。このファイルを実行すると、Gazeboのワールドが立ち上がり、上で説明した1〜4のノードやコントローラが一斉に起動します。
- **関係性**: `teleop_twist_joy` の設定（どのスティックで動かすか）や、コントローラの起動タイミングなどがここに書かれています。

### 📁 `urdf/ros26a_urdf.xacro` (および連携するファイル)
**ロボットの「体（物理モデル）」を定義するファイル**です。
- **`ros26a_urdf.xacro`**: ロボットの見た目（Visual）、当たり判定（Collision）、重さ（Inertial）、そして関節（Joint）を定義しています。今回、関節名やリンク名を英語（`wheel_front_left_joint` など）に書き換えました。
- **`ros26a_urdf.gazebo`**: 車輪の摩擦係数（`mu1`, `mu2`）や、Gazeboと `ros2_control` を繋ぐプラグイン（`gz_ros2_control`）の宣言が書かれています。
- **`ros26a_urdf.ros2control`**: `ros2_control` に対して「この4つのジョイント（車輪）を速度制御(Velocity)で動かす」というハードウェアの仕様を宣言しています。

### 📁 `config/ros2_controllers.yaml`
**モーター制御の設定ファイル**です。
- **役割**: `ros2_control` に対して、`omni_wheel_controller`（4つの車輪をまとめて動かすコントローラ）を定義し、どのジョイントを制御対象にするかを設定しています。

### 📁 `robot26a_urdf/omni_kinematics_node.py`
**対角オムニ（X-drive）の「脳」にあたるPythonプログラム**です。
- **役割**: スティックを「前」に倒したとき、前進するために左前と右後ろの車輪をどう回し、右前と左後ろをどう回せばいいかという計算を行っています。

## 3. 「ここをいじったらこうなる」カスタマイズガイド

ロボットの動きを変えたい場合は、以下の場所を編集します。

### A. スピードをもっと速く/遅くしたい
**変更ファイル**: `launch/gazebo.launch.py`
`teleop_node` の設定部分に注目してください。
```python
'scale_linear.x': 1.0,  # 前後方向の最大スピード（数値を大きくすると速くなる）
'scale_linear.y': 1.0,  # 左右平行移動の最大スピード
'scale_angular.yaw': 1.0 # 旋回（回転）の最大スピード
```

### B. 操作するスティックやボタンを変更したい
**変更ファイル**: `launch/gazebo.launch.py`
同じく `teleop_node` の設定部分です。
```python
'axis_linear.x': 1, # 現在は左スティックの上下。別の軸に変えたい場合はここを変更
'axis_linear.y': 0, # 現在は左スティックの左右。
'axis_angular.yaw': 3, # 現在は右スティックの左右。
'require_enable_button': False # これを True にし、'enable_button': 0 などを追加すると「Aボタンを押しながらでないと動かない」といった安全機能を追加できます。
```
※ コントローラの軸番号（0,1,2...）を調べるには、別のターミナルで `ros2 topic echo /joy` を実行しながらスティックを動かすと確認できます。

### C. 斜め移動や回転の「混ざり具合」がおかしい（キネマティクスの微調整）
**変更ファイル**: `robot26a_urdf/omni_kinematics_node.py`
ロボットの物理的なサイズ（車輪の半径や、中心から車輪までの距離）と計算式のパラメータがズレている場合、直進しようとしても少し斜めに曲がったりします。
```python
self.declare_parameter('wheel_radius', 0.05) # 車輪の半径（メートル）
self.declare_parameter('robot_radius', 0.54) # 車輪の配置半径
```
ここを実際のロボットの寸法（CAD寸法）に合わせることで、より正確な挙動になります。

### D. 物理的に滑りすぎる、またはガタガタする（Gazeboの摩擦）
**変更ファイル**: `urdf/ros26a_urdf.gazebo`
オムニホイールの挙動はシミュレーター上では摩擦係数で表現されます。
```xml
<gazebo reference="wheel_front_left_link">
  <mu1>0.2</mu1> <!-- 前後方向の摩擦 -->
  <mu2>0.2</mu2> <!-- 横方向（オムニのローラーが滑る方向）の摩擦 -->
</gazebo>
```
※ `mu2` を `0.0`（完全に滑る）にするとシミュレーション内で横滑りが発生しなくなって動かなくなるケースがあります。その場合は `0.1` や `0.2` など少し摩擦を持たせるか、`<fdir1>`タグで摩擦の方向を明示する必要があります。現在動かない問題への対処として `0.2` に戻してあります。
